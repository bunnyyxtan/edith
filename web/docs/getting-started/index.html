Getting Started

From a new wallet connection to a verified paid response. Nothing is paid during setup; you approve each payment separately in your wallet.

1. Check the requirements

Use a browser with a Sui Wallet Standard wallet, such as Slush. Unlock a Mainnet account and ensure it has enough SUI for the quoted payment and network fees. You also need an agent or script that can send HTTP requests with an Edith agent key.

Live payments. The deployed app uses Sui Mainnet. If your wallet displays a security warning, stop and assess it. These steps do not require bypassing wallet warnings.

2. Connect a wallet and sign in

Open Open Edith, select Connect wallet, and choose a detected wallet. Approve the connection in the wallet. Edith then asks you to Sign to prove it's you.

The sign-in message includes the site, wallet address, network, nonce, and expiry. It proves control of that address and creates a session. It does not transfer SUI or authorize future payments. Edith asks for a separate transaction signature for each payment you approve.

3. Connect an agent

Open Agents. Under Connect your first agent, enter an Agent name you will recognize in Activity, then select Create agent key. Copy the key while it is shown. Edith stores a fingerprint and cannot show the secret again. If you lose it, disconnect that agent and create another.

Give the key only to the agent you trust. It can ask Edith about paid URLs and read its own requests. It cannot approve or send a wallet payment. See Agent Integration for the API.

4. Set spending limits

Open Limits. Review Most per payment and Most in 24 hours, then select Confirm these limits or choose your own values. The 24-hour limit is rolling. Payments still settling count toward it. Edith also applies a 0.01 SUI hard ceiling per call.

If this wallet has unreconciled historical payments, Edith holds new payments until those records are checked. Changing a limit does not remove that hold.

5. Ask for a paid API response

Your agent sends POST /v1/requests with a JSON url and its key in Authorization: Bearer <key>. Edith checks the URL, memory, limits, and the provider's quote. Submitting the request does not pay.

Example request · replace the key
curl -X POST 'https://edith-sooty.vercel.app/v1/requests' \
  -H 'Authorization: Bearer YOUR_AGENT_KEY' \
  -H 'Content-Type: application/json' \
  --data '{"url":"https://edith-sooty.vercel.app/demo/quote?ticker=SUI"}'

The bundled Quote Desk URL above is a paid Mainnet demo provider. Its quote is 0.001 SUI. For a no-payment look at the flow, visit the guided demo and read the steps without running them.

6. Review and approve

If the response state is awaiting, open its approval.review URL or find it in Overview and Activity. Review the provider, amount, payee, and Edith's decision. Approve only if they match what you intended. Your wallet then asks you to sign the exact transfer. You may decline it.

If the quote has expired, Edith fetches a fresh price and checks memory and limits again when you review. A request can wait for approval for up to 24 hours.

7. Read the result and evidence

Poll GET /v1/requests/:id with the same agent key. A paid result includes the response body, Sui transaction digest, and, when saved, a Walrus Memory blob ID. Activity shows the decision and evidence to the wallet owner. A blocked result has a reason and no payment; free means the provider did not require payment.

For uncertain settlement, leave the payment reserved and use the app's recheck action. Do not pay the same request again until Sui evidence resolves it. Learn how this works in Payments & Memory.
